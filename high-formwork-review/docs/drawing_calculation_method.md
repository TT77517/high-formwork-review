# 图文一致性校验与计算校核 —— 实现方法（现状 · 已修 · 演进路线）

> 2026-08-23 整理。样例验证数据：任务 `c26377dc`（高支模方案.pdf，214 页）。

## 一、图文一致性校验（drawing_review.py）

### 1.1 现状架构

```
正文参数（project_facts，参数抽取引擎确认值）
        │
        ▼
图纸页筛选（page_type ∈ {drawing, mixed, image} 或含 image/figure/chart block）
        │
        ▼
关键词+数值正则提取（DRAWING_CROSS_CHECK_PARAMS：步距/悬臂/纵距/横距/高度 5 参数）
        │
        ▼
单位归一（<50 推测为 m → mm）→ 5% 容差比对 → PASS / ISSUE / REVIEW
```

5 个参数 + 1 条 DR-90 证据召回卡。输出 `drawing_review.json`，前端有"正文值 vs 图纸标注值"双列卡片。

### 1.2 本轮修复的三个误报根因（实测样例验证）

| 问题 | 根因 | 修复 |
|------|------|------|
| DR-01 步距 ISSUE（正文1.5 vs "图纸4.0"） | ① 把规范条文"架体高度超过4m…"当图纸标注；② 代表值取第一个命中值 | ① `_is_spec_clause_quote` 过滤"不得大于/严禁超过…"等限值表述；② 代表值改众数（`_representative_value`） |
| DR-02 悬臂 ISSUE（正文450 vs "图纸13.88"） | "托撑"关键词命中支架名称行"**托撑+承插型插槽式** 搭设高度13.88"；"悬臂"命中"悬臂端计算长度折减系数k 0.7" | 关键词改完整表述（悬臂长度/顶托悬臂/悬臂长/伸出顶层），不再用单词"托撑"/"悬臂" |
| DR-04 横距 ISSUE（正文1.2 vs 图纸900） | 多部位工程同一参数有多个合法值（梁下1200、板下900），单一代表值比对必然误报 | 图纸值集合中**任一值**命中即 PASS；ISSUE 时结论里列全部标注值 |

修复后实测：5 条全部 PASS（修复前 2 真 PASS + 3 误报 ISSUE）。

### 1.3 方法边界与演进路线

**当前边界**：只做"图纸页**文本层**标注"的交叉比对。MinerU 解析出的图纸文字（规格表、参数表）可命中；**纯尺寸线/图形内嵌数字若不在文本层则不可见**。

**演进三级**：

1. **表格感知提取（近期，纯规则）**——当前正则在整页拼接文本上跑，跨行误取风险仍在（DR-02 的 0.7 就是跨词命中）。改为：只在**单个 block**内做 关键词→数值 配对（表格 block 的 cell 结构 MinerU 已给出 `table_html`），彻底消灭跨行误取；并给每个参数配置 `expected_range`（如悬臂 0~700mm）作护栏。
2. **视觉证据召回（中期，仍不 OCR）**——ISSUE/REVIEW 时把对应图纸页裁剪图 + 正文参数卡一起推给人工复核工作台（复用现有 `human_review_queue` 深链机制），图文证据并排。这是投入产出比最高的一步：机器定位 + 人眼判定。
3. **VLM 尺寸读取（远期，可选）**——图纸页走视觉模型读尺寸标注。成本高（每页一次 VLM 调用）、准确率受图纸质量制约，建议仅在"文本层完全无标注"的参数上按需触发，不进默认链路。

## 二、计算校核（calculation_engine.py）

### 2.1 现状架构

- 32 条计算规则（check_type=calculation），`FORMULA_KEYWORDS` 每条规则配关键词组；
- `_extract_calculation_segments` 按"计算/验算"章节标记收集计算书文本段（带 block 定位）；
- 判定是**关键词命中率**：`matched ≥ max(2, len/2)` → COMPLIANT，部分命中 → UNCERTAIN；
- **模式是"公式存在性检查"**（mode: formula_existence_check），不做力学复算。

实测样例：18 COMPLIANT / 14 UNCERTAIN。

### 2.2 本质局限

"面板抗弯承载力验算"规则命中了"面板、抗弯、σ、M/W"就判 COMPLIANT——这只证明**方案里写了这个验算**，不证明**算得对**。 UNCERTAIN 的 14 条里相当部分是关键词组在 NFKC/LaTeX 数学块（`$M/W$`、`\sigma`）上失配的假阴性。

### 2.3 演进路线：从"存在性"到"参数一致性"再到"复算"

**第一级（近期）：计算书输入参数 vs 正文参数交叉比对（复用既有资产）**
- `consistency_review.py` 已实现 design/calculation 双侧参数比对（CR-01~04，含 `_looks_like_calculation_candidate` 页码+LaTeX 特征分流），但目前只覆盖 4 个参数；
- 扩展 PARAMETER_LABELS 到高支模核心参数全集（纵/横距、步距、悬臂、高度、壁厚、荷载取值…），使"计算书输入 vs 正文声明"逐参数自动比对——**这是当前数据结构下性价比最高的校核增强**，不需要 LLM。

**第二级（中期）：验算链条完整性检查（规则升级，仍无 LLM）**
- 把"关键词命中"升级为"链条命中"：每条规则定义 需求的输入参数集合 + 输出结论形态（如 面板抗弯：需要 M、W、σ 数值 + σ≤f 结论式）；
- 从计算书 LaTeX block 里数值化抽取（MinerU 数学块保留 LaTeX，`\mathrm{...}` 正则可解析），检查链条是否闭合：有 M 无 W、有 σ 无比较结论 → UNCERTAIN 并说明缺哪环。

**第三级（远期）：确定性复算（符号验算）**
- 对可数值化的验算（长细比 λ=l0/i、悬臂长度限值、壁厚构造），抽取输入参数后**本地重算**并与方案结果比对——32 条规则中约 1/3 是纯代入公式，可确定性复算；
- 复杂的稳定/倾覆验算涉及系数查表（φ、η、k），表值内置于规则库后同样可算。这一级输出的是真正的 VIOLATED（算错了），而不是 UNCERTAIN（没找到）。

**LLM 的角色**：与图文校验相反，计算校核里 LLM 不宜做主力——数值复算要确定性。LLM 适合的位置是第一/二级的"参数抽取兜底"：规则抽不到的输入参数（表格变形、LaTeX 混乱）交给语义审查 Workflow 的批次一起抽，回填 facts 后再走确定性比对。即：**LLM 抽参数，规则做判定**。
